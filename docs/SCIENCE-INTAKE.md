# Shared production inquiry service

Events production binds SCIENCE_INTAKE to the existing ymg-science-website Worker. It validates origin, fields and its own rate limit first, then forwards the form internally to /api/assessment using the Events request origin. Science verifies the single-use Turnstile token against that hostname and action assessment, then uses its existing authenticated Google Apps Script / Workspace relay. No Science secret or code is copied or changed. The existing root-domain Turnstile widget authorizes its subdomains.

The public configuration exposes only readiness, site key and action. Every event field is mapped to the existing schema; notification subject is New Live Events inquiry — sender name. Previews cannot use this production adapter: it accepts only the `https://events.ymgconsultingservices.com` request origin, so `wrangler.json` previews (no binding) and version URLs of the production Worker (binding present, other origin) both report the form unavailable. The independently configured direct transport (`TURNSTILE_*`, `GOOGLE_RELAY_*`) is retained only for isolated deployments with their own secrets; production sets none of them, so it is not a production recovery path.

If intake fails, `/api/events/health` reports the `intake` category and the alerts in [analytics operations](ANALYTICS-OPERATIONS.md#health-endpoint) fire. Recovery is on the Science side (its Worker, Turnstile widget or Apps Script relay) or a missing binding in `wrangler.production.json`; see [current production state](../deploy/README.md#current-production-state).

A service acceptance is not final mailbox delivery. A real human form submission and inbox receipt remain the final delivery check; invalid-token checks must reject without sending mail. Do not bypass Turnstile or publish relay credentials.
