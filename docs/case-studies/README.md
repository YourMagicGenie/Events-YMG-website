# YMG Events case studies

This folder holds only blank templates and publication instructions. The Events
repository is public, so **do not put private drafts, signed releases, client
contact details, guest information, unpublished photographs or confidential
commercial terms in this repository**.

## Draft and release path

1. Copy [TEMPLATE.md](TEMPLATE.md) into a private owner-controlled workspace.
   Keep source evidence and permission records there. Do not start a public
   story until a real event has taken place.
2. Complete the fact check and rights checklist in the template. Obtain
   explicit written permission from the client/venue for the exact public
   story, names, quote and channels. Obtain permission from the photographer or
   other rights holder for each selected image, and releases for identifiable
   attendees where needed. A venue booking alone does not grant photo or
   testimonial rights.
3. Verify every outcome against a dated source. Record the source and a
   meaningful denominator for rates or percentages. Omit outcomes that cannot
   be substantiated or safely disclosed. Do not turn a single result into a
   general guarantee.
4. Have the owner review the final factual copy, rights, redactions and
   English/Italian wording. Record the approval date and approved channels.
   Keep the original permission evidence private; this public repository only
   receives material expressly cleared for publication.
5. Only after all gates pass, create the public page at
   `dist/case-studies/<slug>/index.html`, add that canonical URL to
   `dist/sitemap.xml`, and link it from the site through a separate reviewed
   PR. Follow the current site’s typography, palette, navigation, privacy and
   mobile patterns. Do not add a listing or link before the individual page is
   ready.
6. If permission expires or is withdrawn, remove or revise the page and its
   sitemap entry promptly, preserving only a private record that the owner is
   permitted to retain.

## Publication gates

Use the status values from the template in order: `PRIVATE DRAFT`, `FACT
CHECKED`, `RIGHTS CLEARED`, `OWNER APPROVED`, `PUBLISHED` or `WITHDRAWN`. A
public page requires `OWNER APPROVED`; the first four states must never be
rendered by the site. This folder is not read by a site build and is outside
`dist`.

No event, client, venue endorsement, testimonial, attendance figure, ticket
result, revenue figure or other outcome is currently approved for use as a YMG
Events case study. Existing concept examples remain prospective formats, not
past-event evidence.
